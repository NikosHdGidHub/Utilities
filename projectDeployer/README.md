# Project Deployer

Настольная утилита на Python 3.11+ и Tkinter создаёт проект в новой папке, устанавливает зависимости, записывает документацию и делает локальный коммит. Интерфейс и документация проектов — на русском языке.

## Быстрый старт

1. Установите Python 3.11+ с Tkinter и Git 2.28+. Для React рекомендован Node.js 24 LTS с npm и доступом к реестру пакетов. Для публикации установите GitHub CLI и выполните `gh auth login`.
2. Откройте каталог `projectDeployer` и запустите `python main.py`.
3. Выберите пресет, введите название проекта и укажите родительский каталог. Имя папки заполняется автоматически. После ручного редактирования кнопка **Как название** восстанавливает автозаполнение.
4. Нажмите **Создать проект** и проверьте путь в диалоге. На вопрос о GitHub по умолчанию выбрано «Нет». Для публикации укажите имя, выберите Private или Public и подтвердите выбор.
5. Откройте созданный каталог. В `README.md` есть команды запуска, в `CHEATSHEET.md` — команды для дальнейшей работы. Шпаргалку можно посмотреть и до создания проекта.

В Debian/Ubuntu системному Python могут понадобиться `python3-tk` и `python3-venv`. Чтобы явно выбрать Python для создаваемого окружения, задайте переменную `PROJECT_DEPLOYER_PYTHON` с путём к интерпретатору.

## Пресеты

| Название | Содержимое |
|---|---|
| Python Basic | Консольное приложение, пустой requirements.txt, pip и .venv |
| React Basic | Vite, React, TypeScript, CSS, Button, Card, Counter и Toggle |
| React Tailwind | React Basic со стилями Tailwind CSS и плагином для Vite |
| React Router | React Basic с маршрутами Home и About и общим Layout |
| React Full | Компоненты Tailwind и Router вместе |

Для Python запускайте `.\.venv\Scripts\python.exe main.py` в Windows или `.venv/bin/python main.py` в Linux/macOS. В React-проекте выполните `npm run dev`. Сборка и lint доступны по командам `npm run build` и `npm run lint`.

## Настройки и журнал

**Каталог по умолчанию…** записывает выбранный путь в `settings.json` рядом с программой. При первом запуске запись содержит домашний каталог. **Обзор…** меняет путь для текущего проекта. Для сохранения настройки нужны права записи в каталог установки.

**Обновить шаблоны** повторно читает JSON и файлы, обновляет описание и предпросмотр, сохраняет выбор по ID. При ошибке обновления работает предыдущий снимок, включая содержимое файлов. Ошибки перечисляются во вкладке **Журнал**. Во время создания проекта изменение параметров заблокировано. Журнал хранится в памяти и очищается для следующего проекта.

## Расположение файлов

- `main.py`, `gui.py` — запуск и интерфейс. Фоновый поток передаёт события через очередь, диалоги обрабатывает главный поток Tk.
- `presets.py` — загрузка, проверки, разрешение наследования и построение плана в памяти.
- `deployer.py` — выполнение этапов, обработка ошибок и частичных проектов.
- `common.py` — пути, переменные и выполнение команд с передачей stdout и stderr в GUI.
- `git_ops.py`, `github.py`, `config.py` — Git, публикация и настройки.
- `templates/` — редактируемые определения и файлы, `templates/features/` — компоненты.
- `tests/` — автоматические проверки.

Дополнительные шаблоны можно разместить в `%APPDATA%\ProjectDeployer\templates` (Windows), `~/Library/Application Support/ProjectDeployer/templates` (macOS) или `$XDG_CONFIG_HOME/ProjectDeployer/templates` (Linux, по умолчанию `~/.config/ProjectDeployer/templates`). ID уникален для обоих каталогов.

## Добавление пресета

Создайте `templates/my-python/template.json` со следующим содержимым и нажмите **Обновить шаблоны**. Проект унаследует Python Basic и получит дополнительный каталог.

```json
{
  "version": 1,
  "id": "my-python",
  "name": "Python с примерами",
  "description": "Консольное приложение с каталогом examples",
  "extends": "python",
  "mkdir": ["examples"],
  "remove": ["unused.txt"],
  "stages": {
    "Finalize": [
      {"label": "Версия интерпретатора", "args": ["python", "--version"], "required": false}
    ]
  }
}
```

`name` и `description` обязательны. Для совместимости со старыми шаблонами без ID используется имя каталога. Поддерживается версия схемы 1. `extends` ссылается на один родительский ID, `features` содержит упорядоченный список ID. Узлы с `"component": true` доступны для подключения и скрыты из списка GUI. Последовательно применяются предки, компоненты и сам пресет. Повторная ссылка на один ID включает его один раз. Цикл и неизвестный ID считаются ошибками.

В `files/` поместите файлы для нового проекта. Поле `files` позволяет выбрать другой каталог рядом с JSON. Дочерний файл с тем же путём заменяет родительский. Итоговая карта должна содержать непустой UTF-8 файл `CHEATSHEET.md`. Для пустых каталогов используйте `mkdir`. Удаление через `remove` выполняется до записи итоговых файлов. Пути задаются относительно проекта. Абсолютные пути, сегменты `..` и переход через ссылки запрещены.

### Этапы и команды

Порядок этапов фиксирован: Prepare → Scaffold → Dependencies → Cleanup → Files → Finalize → Git → GitHub. На Cleanup обрабатывается `remove`, на Files создаются каталоги и копируются итоговые файлы, затем выполняются команды этих этапов. На Git после пользовательских команд создаётся коммит. GitHub выполняется только при выборе публикации.

Команда содержит `label` и массив `args`, первый элемент которого — исполняемый файл. `args_windows` позволяет заменить массив на Windows. Программа ищется в PATH, путь с префиксом `./` разрешается относительно нового проекта. Старые поля `commands` и `post_commands` поддерживаются на Scaffold и Finalize соответственно. В новых пресетах используйте `stages`.

В аргументах и UTF-8-файлах доступны `{{project_name}}`, `{{folder_name}}`, `{{package_name}}`, `{{project_name_json}}` (строковый литерал с кавычками) и `{{project_name_html}}` (экранированный HTML-текст). Для бинарных файлов сохраняются исходные байты. Команды передаются отдельными аргументами без shell. Для Windows batch-файлов поддерживаются только простые аргументы без пробелов и управляющих символов оболочки. Локальные JSON считаются доверенными, их команды исполняются с правами пользователя.

### Зависимости и версии

Встроенная React-база вызывает `npm exec --yes --engine-strict --package=create-vite@9 -- create-vite . --template react-ts --no-interactive --no-immediate`. Используется последняя стабильная версия в поддерживаемой ветке генератора. Диапазоны React, TypeScript, Vite и lint задаёт официальный шаблон. npm разрешает версии с учётом engines и peerDependencies через `npm install --engine-strict --strict-peer-deps`. Плагины ограничены поддерживаемыми API Tailwind 4 и React Router 7. Lock-файл сохраняет версии конкретного проекта, `npm ci` воспроизводит установку. При переходе на новый основной API сначала обновите шаблон и прогоните интеграционные тесты.

Python создаёт `.venv` установленным интерпретатором и выполняет `python -m pip install -r requirements.txt` из этого окружения. В дочернем пресете перечислите пакеты в своём `files/requirements.txt`. pip по умолчанию выбирает стабильные версии с учётом ограничений пакетов и интерпретатора.

## Git, GitHub и ошибки

Проект получает собственный `.gitignore`, ветку `main` и коммит `Initial commit`. Если автор не задан, укажите `git config user.name "Имя"` и `git config user.email "Почта"` в частично созданном репозитории, затем нажмите **Повторить**. Приложение не меняет глобальную конфигурацию.

При выборе GitHub утилита проверяет авторизацию на github.com, создаёт репозиторий для текущего аккаунта через `gh api`, добавляет `origin` и отправляет main. После подтверждённого создания при повторе используется тот же репозиторий. Если сервер создал репозиторий, но ответ потерялся, утилита не присоединяет одноимённый репозиторий автоматически. Проверьте его в аккаунте перед ручным продолжением. Ошибка публикации оставляет локальный проект на диске.

Ошибка команды позволяет посмотреть журнал, повторить текущую команду или завершить работу. Пропуск доступен только при `"required": false`. После пропуска или неудачной публикации проект получает статус «Создан с предупреждениями». При ошибке обязательной операции частичный каталог по умолчанию сохраняется. Для удаления нужны два подтверждения. Уже существующие каталоги исключены из развёртывания. Удалённые репозитории утилита не удаляет.

## Автоматические проверки

Из `projectDeployer` запустите:

```sh
python -m unittest discover -s tests -v
```

Для полного прогона нужны рабочий стол (либо `xvfb-run -a` в Linux), Git, Node.js, npm, доступ к npm и модуль venv. Тесты создают проекты во временных каталогах. Тестовая Git-идентификация действует только в процессах тестов. Для GitHub используются имитации.

Дополнительная проверка собранных React-страниц в Chromium, в PowerShell:

```powershell
python -m pip install playwright
python -m playwright install chromium
$env:DEPLOYER_BROWSER_TESTS = "1"
python -m unittest discover -s tests -v
```

Можно задать `CHROMIUM_PATH` с путём к установленному Chromium. В Linux задайте переменные через `export`.

## Сборка Windows EXE

В PowerShell из каталога `projectDeployer`:

```powershell
py -3 -m pip install pyinstaller
py -3 -m PyInstaller --clean --onefile --windowed --name ProjectDeployer main.py
Copy-Item -Recurse -Force templates dist
.\dist\ProjectDeployer.exe
```

Распространяйте `ProjectDeployer.exe` и каталог `templates\` рядом с ним. `settings.json` создаётся при первом запуске. Для самой программы Python на компьютере пользователя не нужен. Для Python-проектов требуется внешний Python, для React — Node.js и npm, для всех проектов — Git.

Для проверки перенесите комплект в отдельный каталог с пробелами и кириллицей, запустите EXE, измените описание в JSON и обновите список. Создайте Python Basic и React Full. Проверьте запуск Python из .venv, npm run build, ветку main и git log -1. Убедитесь, что настройки читаются после перезапуска.
